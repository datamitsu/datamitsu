# `datamitsu llms` — Implementation Plan (Committed-Snapshot, Decoupled Build)

**Status:** Ready to implement · **Stage:** alpha · **Date:** 2026-07-23
**Owner:** CLI/docs · **Plan file:** `docs/plans/2026-07-23-datamitsu-llms-command.md`

> Scope note: this plan intentionally does **not** ship a full-corpus (`llms-full`) dump. The
> command serves the root index and one page at a time. `llms-full.txt` parity, a `--full` flag,
> and the runtime concatenation machinery are explicitly out of scope.

---

## 1. Context & Discovery

The goal is a `datamitsu llms` command that lets an LLM agent pull the project docs straight from
the installed binary — offline, no network, always matching the binary's own version:

- `datamitsu llms` → a self-describing root index that lists every page as a copy-paste-ready
  `datamitsu llms <slug>` call, so the agent can pick its own next request.
- `datamitsu llms <page>` → one cleaned Markdown page on stdout.
- A machine-readable list and provenance surface (`--list`, `--json`).
- A build-time guarantee that the embedded docs and the binary are the same version.

**The pivotal discovery:** the artifacts already exist. `website/` uses
`@ovineko/docusaurus-config → withOvinekoDocs`, which bundles `docusaurus-plugin-llms@0.4.0` with
`{ generateLLMsTxt, generateLLMsFullTxt, generateMarkdownFiles, excludeImports, removeDuplicateHeadings }`.
Running `docusaurus build` emits into `website/build/`:

- `llms.txt` — an [llmstxt.org](https://llmstxt.org) root index over all **50** pages.
- `docs/<slug>.md` — 50 cleaned per-page files (JSX/imports stripped, admonitions/Tabs flattened),
  each starting `# Title\n> description\n`.
- `llms-full.txt` — full concatenation. **We ignore this file** (out of scope).

`website/build/` is gitignored (`**/build/`), so nothing is committed today. We do **not** need to
write a docs cleaner — we harvest the plugin's per-page output.

### Central architectural decision: committed snapshot, decoupled from `go build`

The repo has two on-disk precedents, and they are **not** equal:

| Precedent                                  | Committed?                | Consequence                                                                                                     |
| ------------------------------------------ | ------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `internal/config/config.js` (+`.d.ts`)     | generated, **gitignored** | The direct cause of "`go install` does NOT work"; a plain `go build` fails without a preliminary `tsdown` step. |
| `website/docs/reference/parser-catalog.md` | generated, **committed**  | Regenerated by `task gen:parsers-doc`, drift-checked in CI. `go build` needs no Rust/node.                      |

We choose the **parser-catalog side of the fork.** The docs snapshot is generated by a harvest task
but **committed** into `internal/llmsdocs/embed/` and embedded via `//go:embed`. Therefore:

- Plain `go build`, the `test/cli` instrumented build, and every contributor without the website
  toolchain compile the docs straight from git — **zero Docusaurus/node on the build path.**
- The release-from-tag flow plus a **path-filtered CI `git diff --exit-code` drift gate** provide
  the version guarantee _structurally_, without coupling `go build` to a multi-minute Docusaurus
  build (which today runs only on release tags).
- Accepted downside — the committed snapshot can lag source between harvests — is mitigated by the
  drift gate + a lefthook guard on `website/docs` changes. This is the exact bargain
  `parser-catalog.md` already makes.

**Rejected — generate-hermetic (embed from gitignored `website/build/`):** re-imposes a
node+Docusaurus prerequisite on every `go build` and breaks the offline `test/cli` golden tier,
whose compiled binary could not build without harvesting the gitignored embed first. That is the
`config.js` trap; we refuse to extend it.

### Provenance, not schema-diff

Only `parser-catalog.md` is schema-derived; `cli-commands.md`, `configuration-api.md`, etc. are
hand-authored prose. So "embedded docs and the CLI/config schema are the same version" **cannot**
mean semantic equality — it means **build provenance**: the embedded snapshot was harvested from
the same source tree that built this binary. The drift check is a deterministic content-fingerprint
gate, never a schema diff. (One cheap, mechanical exception is added in §7: a docs↔CLI leaf-name
assertion.)

## 2. Command Surface

New leaf command `cmd/llms.go`, registered on `rootCmd`.

```
Use:   "llms [page]"
Short: "Print project documentation as LLM-friendly markdown (offline, embedded)"
```

Arg-count and flag-conflict validation live **inside** `RunE` (not a cobra `Args` validator) so we
control the exit code precisely (§6).

### Behaviors

| Invocation                       | Stdout                                                                   | Exit |
| -------------------------------- | ------------------------------------------------------------------------ | ---- |
| `datamitsu llms`                 | embedded `index.txt` (rewritten root index, CLI-slug links)              | 0    |
| `datamitsu llms <page>`          | resolved page's cleaned markdown, verbatim                               | 0    |
| `datamitsu llms --web`           | standard llmstxt.org index with real `https://datamitsu.com/docs/…` URLs | 0    |
| `datamitsu llms --list`          | all canonical slugs, sorted, one per line                                | 0    |
| `datamitsu llms --list --json`   | JSON array `[{slug,aliases,title,description,bytes,contentHash}]`        | 0    |
| `datamitsu llms --json` (no arg) | provenance/manifest object (§7)                                          | 0    |
| `datamitsu llms <page> --json`   | `{slug,title,description,url,bytes,contentHash,body}`                    | 0    |

### Flags

- `--list` (bool): print resolvable canonical slugs, sorted; ignores any positional arg.
- `--json` (bool): machine-readable, per the table above. Honors "Introspectable by Design."
- `--web` (bool): re-emit the **standard** llmstxt.org index — real fetchable `.md` URLs instead of
  CLI slugs — reconstructed from the per-page `url` stored in the manifest. This preserves a
  faithful, standards-compliant `llms.txt` for external consumers, while the default
  `datamitsu llms` output is optimized for the in-binary agent. Mutually exclusive with a positional
  arg. (Answers the "root output diverges from llmstxt.org standard" concern by making the
  divergence a deliberate, documented default with an opt-out.)

### Contracts

- **Stdout is content-only.** Page/index/JSON goes to **stdout**; every diagnostic (unknown page,
  ambiguity, usage) goes to **stderr**, so `datamitsu llms about | your-agent` is clean.
- **No ANSI, no spinners, no `Display` scope.** Pure text/markdown. The command performs **zero
  network I/O**, needs no cache and no git repo — a deliberate selling point: fully offline,
  embedded-only. It must not open the shared `ui.Display` render path.

## 3. Package & Embed Layout

New package `internal/llmsdocs/`, mirroring `internal/config/`.

```
internal/llmsdocs/
  llmsdocs.go            //go:embed embed  -> embed.FS + public API
  resolve.go             Resolve() pipeline + edit-distance suggestions
  manifest.go            Manifest type (json tags)
  *_test.go
  embed/
    pages/               50 cleaned per-page files, dir structure PRESERVED
      about.md
      intro.md
      contributing/index.md
      contributing/brand-guidelines.md
      getting-started/installation/index.md
      getting-started/installation/npm.md
      guides/architecture/index.md
      guides/architecture/caching.md
      ... (50 total)
    index.txt            rewritten root index (agent header + CLI-slug links)
    manifest.json        deterministic, content-derived provenance (§7)
```

**What is embedded — DECISION:** per-page files + `index.txt` + `manifest.json` **only**. Directory
structure is preserved so full-path slugs never collide on disk (the only basename collision is the
three `index.md`, resolved by index-collapse in §4). `llms-full.txt` is **not** embedded and not
derived — out of scope. The harvester copies only `*.md` under `docs/`; images, `*.cast`, CSS, JS
are never read, and the plugin output is already JSX/import-stripped, so no binary blob can leak.

**Verbatim, not formatted — DECISION (deviation from parser-catalog):** the embedded Markdown is
written **byte-for-byte** as the plugin emitted it (after the deterministic normalization pass of
§7) and is **excluded from all formatters/linters** (add `internal/llmsdocs/embed` to the repo
format/lint ignore set — `.prettierignore` and the `dm fix`/eslint ignore surface). Rationale:
`pageSetHash`/`contentHash` identity must be stable; a reformat would change the bytes and flap the
drift gate. Consequently the harvest task does **not** run `pnpm dm fix` on `embed/`.

### Public API (`llmsdocs.go`)

```go
func Index() string                             // embed/index.txt (CLI-slug form)
func WebIndex() string                          // standard llmstxt.org form, URLs from manifest
func Page(slug string) (Page, bool)             // canonical slug -> page
func List() []string                            // sorted canonical slugs
func Manifest() Manifest
func Resolve(arg string) (slug string, err error) // normalization pipeline

type Page struct {
	Slug, Title, Description, URL, Body string
	Bytes       int
	ContentHash string
	Aliases     []string
}

var ErrUnknownPage = errors.New("unknown page")
var ErrAmbiguous   = errors.New("ambiguous page")
```

## 4. Slug Resolution

### Index-collapse (structurally removes the only collision)

The three `index.md` pages are stored on disk under their directory
(`embed/pages/contributing/index.md`) but exposed under the **canonical slug `<dir>`**
(`contributing`), with `<dir>/index` as a bidirectional **alias**. After index-collapse **no
canonical slug's last segment is `index`**, so the `index` basename collision disappears entirely.
`List()` and `index.txt` emit canonical slugs (`contributing`, not `contributing/index`). The
ambiguous-basename error (rule 6) remains as the fallback for any _future_ non-index basename
collision.

### `Resolve(arg)` pipeline (first match wins)

| #   | Rule                                                                                                                                                                                          | Example input → output                                                                      |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1   | Lowercase; trim surrounding whitespace and a single trailing `/`.                                                                                                                             | `About/` → `about`                                                                          |
| 2   | If `arg` parses as an `http(s)` URL, take its path; if it contains `/docs/`, keep the substring after the **last** `/docs/`. Strip a leading `docs/`. Strip a trailing `.md`.                 | `https://datamitsu.com/docs/guides/architecture/caching.md` → `guides/architecture/caching` |
| 3   | **Alias hit:** if the normalized value equals `<dir>/index` and `<dir>` is a canonical index slug, return `<dir>`.                                                                            | `contributing/index` → `contributing`                                                       |
| 4   | **Exact canonical match** against manifest slugs → return it.                                                                                                                                 | `guides/architecture/caching`, `about` → itself                                             |
| 5   | **Basename shorthand:** if `arg` contains no `/` and matched nothing above, collect all canonical slugs whose last segment == `arg`. Exactly one → return it. Zero → fall through to unknown. | `brand-guidelines` → `contributing/brand-guidelines` (contract example)                     |
| 6   | **Ambiguous basename:** >1 match in rule 5 → `ErrAmbiguous` listing candidates (deterministically sorted).                                                                                    | —                                                                                           |
| 7   | Otherwise → `ErrUnknownPage` (triggers did-you-mean, §5).                                                                                                                                     | `instalation` → unknown                                                                     |

Notes: all canonical slugs are lowercase (**enforced at harvest**, §7 — no mixed-case doc path can
silently break rule 4). `about` and `intro` are distinct root pages reachable by exact match and by
basename. An index page is addressable as `<dir>` (canonical) and `<dir>/index` (alias).

## 5. Unknown-Page Handling

On resolution failure, `cmd/llms.go` prints a single clean line to **stderr** (stdout stays empty
for piping) and exits **3** (§6).

**Did-you-mean:** compute Damerau–Levenshtein distance between the normalized arg and both (a) every
canonical slug and (b) every basename; surface up to 3 candidates within a threshold
(`distance ≤ 3` or `≤ 40%` of arg length). Candidates are **sorted by (distance, then slug)** before
truncation so the exit-3 stderr golden is byte-stable under `-count=2`.

```
$ datamitsu llms instalation
unknown page "instalation". Did you mean: getting-started/installation?
Run "datamitsu llms --list" to see all 50 pages.
```

If nothing clears the threshold, drop the suggestion and keep the `--list` pointer. Ambiguous
basename (rule 6) also exits 3 with the sorted candidate list. `--list` / `--list --json` always
exit 0 and never resolve.

### No-description rule

Some pages may have frontmatter without a `description`; the plugin then emits a bare `> ` blockquote
line. **DECISION:** during harvest, detect a lone `> ` (empty blockquote) immediately after the H1
and **drop that line** from the per-page body; set the page's `description` to `""` in the manifest;
and in `index.txt`/`--web` omit the `: <desc>` suffix. We do **not** fall back to the first paragraph
— that would be non-deterministic and would let the body and the manifest drift apart. `--json` returns
`description: ""` for such pages.

## 6. Exit Codes

The whole repo currently uses **only** `os.Exit(1)` (verified: 5 occurrences, no other codes in
`cmd/` or `internal/`), and `rootCmd` sets `SilenceErrors: true` / `SilenceUsage: true`, with
`Execute()` mapping any returned error to `os.Exit(1)`. Codes **2** and **3** are therefore free of
any conflicting convention.

Because this command's purpose is agent consumption, an agent must mechanically distinguish "I mistyped
the page" from "I misused the flags":

| Code | Meaning                                                           |
| ---- | ----------------------------------------------------------------- |
| 0    | success                                                           |
| 2    | usage error — `--web` with a positional arg, or >1 positional arg |
| 3    | unknown or ambiguous page                                         |

**Mechanism:** since `Execute()` always maps a returned error to exit 1, `cmd/llms.go`'s `RunE`
handles codes 2/3 itself — it prints the single stderr line and calls `os.Exit(2|3)` directly, then
returns `nil`. This piggybacks on the already-global `SilenceErrors`/`SilenceUsage`, so there is no
cobra `Error:` prefix and no usage dump — a single clean stderr line, tight goldens, and a clean
stdout pipe contract. We deliberately do **not** set a cobra `Args` validator (which would route to
exit 1); arg-count is validated in `RunE`.

> Open question O1 confirms whether this 0/2/3 deviation is acceptable or should collapse to 0/1.

## 7. Build-Time Provenance / Drift Check

This is **build provenance**, not a runtime schema diff. "Same version" = "this snapshot was
harvested from the source tree that built this binary."

### `manifest.json` — deterministic, content-only

Every field is content-derived. **No timestamps, no live git SHA** — so `git diff --exit-code`
never flaps and release commits are never "one commit stale." Provenance version comes from
`ldflags` at **runtime**, never from the committed file.

```jsonc
{
  "schemaVersion": 1, // manifest format version (int)
  "generator": "llms-harvest/1", // harvester version; bump on format change
  "license": "MIT", // repo SPDX id (from package.json / LICENSE)
  "pageCount": 50, // == len(pages); NOT hardcoded in tests
  "pageSetHash": "3ab7...", // XXH3-128 of the whole page set (identity)
  "pages": [
    {
      "slug": "about",
      "aliases": [],
      "url": "https://datamitsu.com/docs/about.md", // plugin's original link (for --web)
      "title": "About datamitsu",
      "description": "Learn why datamitsu exists and how it helps teams standardize their toolchains",
      "bytes": 4213,
      "contentHash": "1f3a9c...", // XXH3-128 of the page body
    },
    // ... in Docusaurus sidebar order (from llms.txt ToC) — index.txt / --web order
  ],
}
```

**Manifest JSON Schema (informal):**

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["schemaVersion", "generator", "license", "pageCount", "pageSetHash", "pages"],
  "properties": {
    "schemaVersion": { "type": "integer", "minimum": 1 },
    "generator": { "type": "string" },
    "license": { "type": "string" },
    "pageCount": { "type": "integer", "minimum": 1 },
    "pageSetHash": { "type": "string", "pattern": "^[0-9a-f]{32}$" },
    "pages": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "additionalProperties": false,
        "required": ["slug", "aliases", "url", "title", "description", "bytes", "contentHash"],
        "properties": {
          "slug": { "type": "string", "pattern": "^[a-z0-9/-]+$" },
          "aliases": { "type": "array", "items": { "type": "string" } },
          "url": { "type": "string" },
          "title": { "type": "string" },
          "description": { "type": "string" },
          "bytes": { "type": "integer", "minimum": 0 },
          "contentHash": { "type": "string", "pattern": "^[0-9a-f]{32}$" }
        }
      }
    }
  }
}
```

**Hashing policy (CLAUDE.md):** `pageSetHash` and `contentHash` are **internal fingerprints never
compared against network content** → they MUST be **XXH3-128** via `internal/hashutil`
(`XXH3Hex`/`XXH3Multi`), never SHA-256. This is why the harvester is written in Go (not the tsx used
by `parsers-catalog`): one source of truth for the hash algorithm, unit-testable.

- `contentHash` = `XXH3Hex(body)` per page.
- `pageSetHash` = `XXH3Hex` over the **sorted** stream of `slug + "\0" + contentHash` across all
  pages — order-independent identity of the whole set.

**Deterministic harvest (pin the diff gate).** Before hashing/writing, the harvester normalizes so
`git diff --exit-code` cannot flap across maintainer machines/OS/node versions:

1. Force **LF** line endings on every harvested file.
2. Ensure exactly one trailing newline per file.
3. Emit `pages/**` files in a stable path order and `manifest.pages` in Docusaurus ToC order
   (derived from `llms.txt`); `pageSetHash` sorts internally so order never affects identity.
4. Serialize `manifest.json` with sorted object keys and a fixed indent.
5. **Fail** if any canonical slug is non-lowercase (guards rule 4).

### Two enforcement layers

1. **CI drift job `llms-docs-drift`** (+ lefthook pre-commit guard) — the freshness gate.
   - The job **provisions the website toolchain itself** (node + `pnpm install --filter website`),
     independent of the release-only Pages/deploy job (the only other place Docusaurus runs today).
   - It **always** runs `task gen:llms-docs` then `git diff --exit-code internal/llmsdocs/embed`.
     There is **no source-hash short-circuit**: because the job re-renders with the _current_
     toolchain, a Dependabot bump to `@docusaurus/core`, `@ovineko/docusaurus-config`, or
     `docusaurus-plugin-llms` that changes cleaning/flattening is caught — a hash of just
     `website/docs/**` would have missed it. A non-empty diff = the committed snapshot is stale vs
     `website/docs` at HEAD → **fail**. This guarantees release binaries (built from a tagged
     commit) embed exactly that tag's docs.
   - **Path-filter** to trigger on `website/docs/**`, `website/docusaurus.config.*`,
     `website/pnpm-lock.yaml` (toolchain changes), `internal/llmsdocs/**`, `packaging/llms-harvest/**`.
   - **Fragility note (accepted):** `gen:llms-docs` needs a green `pnpm --filter website build`. Per
     project history the site build has had recurring breakages (rolldown, pnpm store poisoning).
     When the site build is red the snapshot can't be regenerated — but that already blocks the
     website itself, so the drift gate adds no _new_ class of block; it is only as available as the
     Docusaurus toolchain, which is a pre-existing constraint.

2. **Go unit test `TestManifestMatchesEmbed`** (runs in default CI via `go test ./...`, no
   Docusaurus): recompute `pageSetHash` from the embedded FS and assert `== manifest.pageSetHash`;
   assert a slug↔file bijection (every manifest slug has a file, no orphan files); assert
   `index.txt`'s slug set == the manifest canonical slug set; assert `pageCount == len(pages)`; and
   assert each manifest `title`/`description` equals the page body's H1/blockquote **and** the
   `index.txt` entry (prevents the title and description drifting apart across the three copies). Catches a hand-edited manifest
   or partial harvest at `go test` time.

### Cheap docs↔CLI provenance assertion (partial fulfillment of the user's "same version" ask)

Add `TestCLICommandsPageCoversLeaves` (Go, default CI): walk the cobra command tree, collect every
leaf command name, and assert each appears in the embedded `reference/cli-commands.md` page. This is
a mechanical, no-Docusaurus check that the documented CLI has not drifted from the actual command
set — the one place where the "docs match the CLI schema" intent _can_ be enforced without semantic
parsing of prose. (Hidden/devtools leaves may be allow-listed as exceptions.)

### Runtime surface (`datamitsu llms --json`, no arg)

Emits `{binaryVersion, imageTag, pageSetHash, pageCount, generator, schemaVersion, license}` where
`binaryVersion = ldflags.Version`, `imageTag = ldflags.ImageTag`. The **dev/unstable policy mirrors
`internal/version/check.go`**: on a plain `go build` (`Version == "dev"`) it appends an advisory
`"unversioned local build"` note and asserts nothing; the SHA-identity guarantee is provided
transitively by the CI drift gate + release-from-tag. Nothing is enforced at runtime — the docs are
inert data.

## 8. Root Index (`embed/index.txt`) and `--web`

`index.txt` keeps the llmstxt.org shape (H1 title, blockquote tagline, `## Table of Contents`) but
during harvest **rewrites every entry** from the plugin's `- [Title](https://datamitsu.com/docs/<slug>.md): desc`
into a copy-paste-ready CLI form and **prepends an agent header**:

```
# Datamitsu
> Your toolchain deserves a home.

Fetch any page with: `datamitsu llms <slug>`.
Machine list:        `datamitsu llms --list --json`.
Standard llms.txt:   `datamitsu llms --web`.

## Table of Contents
- [About datamitsu](about): Learn why datamitsu exists and how it helps teams standardize their toolchains
- [Brand Guidelines](contributing/brand-guidelines): Voice, tone, and style guidelines for datamitsu docs
- [Installation](getting-started/installation): How to install datamitsu on your system   # canonical (index-collapsed)
- ...
```

The link target is the exact `datamitsu llms <slug>` argument (canonical slug), so an agent picks
its next call without reverse-engineering a URL — this is the command's highest-leverage UX feature,
and the reason the default output **intentionally diverges** from the standard `llms.txt`. Entries
with an empty description omit the `: <desc>` suffix (§5).

`datamitsu llms --web` re-emits the faithful standard index using each page's stored `url`, for
external/standards-compliant consumers — so the divergence is a deliberate default, not a lost
capability.

## 9. Size, Assets, Licensing

- **Size:** 50 per-page `.md` ≈ 375 KB + `index.txt` ≈ 8 KB + `manifest.json` ≈ 15–25 KB ≈
  **~400 KB** on a ~41 MB binary = **<1%**. (Not embedding `llms-full.txt` — out of scope — keeps
  this small.)
- **Compression — DECISION: none.** Go embed stores raw; 400 KB is negligible. Raw keeps the read
  path trivial (`embed.FS.ReadFile → stdout`), keeps the text searchable in the shipped binary, and
  avoids a decompress step. Revisit only if the docs set grows an order of magnitude.
- **Asset exclusion:** the harvester globs `website/build/docs/**/*.md` **only** — images, `*.cast`,
  CSS, JS are never read. A test asserts no embedded page exceeds a sane byte ceiling (asset-inline
  guard).
- **Licensing:** the docs are first-party datamitsu content in this repo under the project's own
  **MIT** license (`package.json`, `LICENSE`). Embedding our own docs into our own binary creates no
  new obligation, so no `NOTICE`/attribution file is added. `manifest.license` records `"MIT"` for
  provenance. **Alpha caveat:** this is not verified against actual page content; a follow-up should
  scan the 50 pages for substantial third-party quotes before the first stable release (documented
  in `maintain-wrapper.md`).

## 10. Assumptions & Guards

- **Single-version, non-i18n docs.** The slug→file mapping and `pageCount` assume one docs version
  and no i18n locales. **Guard:** the harvester **fails** if it detects `website/versioned_docs/` or
  `website/i18n/<locale>/` beyond the default, with a message pointing here. `pageCount` is
  **derived** (`len(pages)`), and `TestManifestMatchesEmbed` asserts `pageCount == len(pages)` —
  never a hardcoded `== 50` — so adding a real page is a manifest/golden update, not a test rewrite.
- **Lowercase canonical slugs** enforced at harvest (§7) so `Resolve()`'s lowercasing can't silently
  miss a mixed-case path.
- **Exit codes 2/3** verified free of any existing repo convention (§6).
- **No network, no git, no cache** — asserted by the blackbox suite running in the fully offline
  `clitest` sandbox.

## 11. Build Wiring

New Taskfile task `gen:llms-docs`, modeled on `gen:parsers-doc`:

```yaml
gen:llms-docs:
  desc: Harvest cleaned docs from the Docusaurus build into the committed embed snapshot.
  cmds:
    - pnpm --filter website build # emits website/build/{llms.txt,docs/**}
    - go run ./packaging/llms-harvest # writes internal/llmsdocs/embed/**
    # NOTE: deliberately NO `dm fix` on embed/ — pages are verbatim & format-ignored (§3).
```

- **`packaging/llms-harvest/main.go`** — a standalone Go `main` in its **own package, not compiled
  into the datamitsu binary.** It reads `website/build/{llms.txt,docs/**/*.md}`, applies the
  normalization pass (§7), writes `embed/pages/**` (verbatim), applies index-collapse aliasing (§4)
  and the no-description rule (§5), rewrites `embed/index.txt` (agent header + CLI-slug links),
  captures each page's original `url`, and writes the deterministic `embed/manifest.json` (XXH3 via
  `internal/hashutil`, page order from the `llms.txt` ToC). **DECISION: standalone, not a hidden
  `devtools llms-harvest` leaf** — keeps it out of the shipped 41 MB binary and off the
  `TestContractCompletenessGate` leaf set.
- **`task build` is UNCHANGED** — it stays `deps:[build:lib] → go build → pack:prepare` and does
  **not** depend on `gen:llms-docs`. The committed snapshot is the build input. `gen:llms-docs` runs
  only at doc-authoring time and in the `llms-docs-drift` CI job — never on the `go build` /
  `test/cli` hot path.

## 12. Phased Implementation Checklist

### Phase 0 — Harvest tooling + committed snapshot

1. Add `packaging/llms-harvest/main.go`: read `website/build/{llms.txt,docs/**/*.md}`; normalize

## 13. Testing Plan (summary)

- **Provenance/identity** — `TestManifestMatchesEmbed` runs in default `go test ./...` (no
  Docusaurus) and is the first line of defense against a hand-edited manifest, a partial harvest, or
  a title/description that has drifted apart across its copies.
- **Docs↔CLI** — `TestCLICommandsPageCoversLeaves` mechanically catches the one drift the user's
  "same version as CLI schema" ask can enforce without prose parsing.
- **Resolution correctness** — `TestResolve` + `TestUnknownPageSuggestion` cover every §4 rule,
  index-collapse aliasing, lowercase enforcement, and the did-you-mean threshold + deterministic
  ordering.
- **CLI contract** — the `test/cli` golden suite freezes stdout/stderr/exit-code (0/2/3)
  byte-for-byte under `-count=2`; `TestContractCompletenessGate` forces the leaf to be tested.
- **Freshness** — the `llms-docs-drift` CI job (always re-render + git diff) + lefthook guard make
  it structurally impossible to merge a stale snapshot, and catches toolchain-bump drift a
  source-hash gate would miss.
- **Offline invariant** — blackbox tests run in the hermetic offline sandbox, asserting zero
  network/git/cache dependency.

## 14. Risks & Trade-offs

- **Staleness between harvests** — accepted; mitigated by the always-re-render drift gate + lefthook
  guard. Same bargain as `parser-catalog.md`. Payoff: `go build`, `test/cli`, and node-less
  contributors are unaffected — we avoid the `config.js` trap.
- **Determinism** — a timestamp or live SHA in the manifest would flap the diff; avoided by a fully
  content-derived manifest (XXH3, no time, no SHA) + a normalization pass (LF, trailing newline,
  sorted keys). Provenance version comes from `ldflags` at runtime.
- **Plugin/toolchain coupling** — a `docusaurus-plugin-llms` or Docusaurus core upgrade could change
  cleaning; the always-re-render drift job (path-filtered to include `pnpm-lock.yaml`) surfaces it,
  where a source-only hash would not.
- **Drift-gate availability** — bounded by Docusaurus build health; a red site build blocks
  regeneration, but that is a pre-existing constraint, not a new one.
- **Standard-vs-CLI index** — the default `datamitsu llms` intentionally diverges from `llms.txt` by
  using CLI slugs; `--web` restores the standard form, so no capability is lost.
- **Residual cost** — one more generated-but-committed artifact for maintainers to regenerate,
  bounded by the drift gate that tells them exactly when. Size (~400 KB, <1%) is immaterial and left
  uncompressed for simplicity and searchable strings.
